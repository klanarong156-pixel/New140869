บัญชีสวน · ระบบบัญชีสำหรับธุรกิจเกษตร
========================================

## ภาพรวม

แอปเว็บแบบ responsive สำหรับบันทึกบัญชีของสวนและธุรกิจเกษตร เน้นต้นทุนการผลิต การขายผลผลิต และตรวจสอบย้อนหลังด้วยสมุดรายวันเดบิต–เครดิต ใช้ Firebase Authentication และ Realtime Database ที่มีอยู่ โดยแยกข้อมูลตามผู้ใช้

## ความสามารถ

- ภาพรวมรายเดือน: รายได้ ค่าใช้จ่าย กำไรสุทธิ จำนวนรายการ และค่าใช้จ่ายสูงสุดตามบัญชี
- สมุดรายวัน: บันทึกรายการหลายบรรทัด ตรวจว่าผลรวมเดบิตกับเครดิตเท่ากันก่อนบันทึก
- ผังบัญชี: มีบัญชีมาตรฐานสำหรับเงินสด ธนาคาร ลูกหนี้ วัสดุเกษตร เจ้าหนี้ ทุน รายได้ผลผลิต และต้นทุนเกษตร พร้อมเพิ่มบัญชีเฉพาะสวนได้
- รายงานรายปีและดาวน์โหลด CSV ที่รองรับ Excel
- ข้อมูลเดิม: อ่านและดาวน์โหลดรายการ `finance` และ `cucumberSales` จาก Firebase เก่าแบบอ่านอย่างเดียว
- รายการใหม่จัดเก็บแยกตามเดือน (`users/{uid}/accounting/journals/YYYY-MM`) เพื่อลดการอ่านข้อมูลทั้งประวัติทุกครั้ง
- รายการสมุดรายวันเป็น create-only ใน Firebase Rules; ไม่แก้หรือลบรายการที่บันทึกแล้ว การแก้ไขทางบัญชีควรทำเป็นรายการกลับบัญชี/ปรับปรุงใหม่

## ความปลอดภัยและข้อมูลเดิม

Firebase Rules จำกัดการอ่านและเขียนของข้อมูลบัญชีไว้เฉพาะผู้ใช้เจ้าของ UID เท่านั้น ยอดเงินเก็บเป็นจำนวนเต็มสตางค์ ระบบหน้าเว็บตรวจสมดุลเดบิต/เครดิตและ Rules ตรวจรูปแบบแต่ละบรรทัด, ผลรวมที่บันทึก, เจ้าของรายการ และห้ามเขียนทับ/ลบ journal entry ที่มีอยู่

Realtime Database Rules ไม่สามารถคำนวณผลรวมของสมาชิกทุกบรรทัดเพื่อยืนยันความเท่ากันได้โดยตรง การตรวจว่ายอดรวมของบรรทัดตรงกับยอดเดบิต/เครดิตจึงทำในแอปก่อนส่ง พร้อมตรวจฟิลด์ยอดรวมซ้ำใน Rules; หากต้องการระดับป้องกันการปลอมข้อมูลข้ามบรรทัด ควรย้ายการ post รายการไป Cloud Function ฝั่งเซิร์ฟเวอร์ก่อนเปิดใช้ในงานบัญชีที่ต้องรับรองตามกฎหมาย

รายการเก่าใน `users/{uid}/finance` และ `users/{uid}/cucumberSales` ไม่ถูกลบ ไม่ถูกแปลงหรือรวมเข้ารายงานใหม่อัตโนมัติ เพื่อป้องกันการบันทึกซ้ำและไม่เดาความหมายของรายการ “ค้างซื้อ” ผู้ใช้เปิดดู/ดาวน์โหลดได้จากเมนูข้อมูลเดิม และนำเข้าด้วยการตรวจสอบรายการก่อนบันทึกใหม่ด้วยมือ

## ตั้งค่า / เปิดเว็บ

1. ใช้ Firebase project เดิมที่กำหนดใน `firebase.js` และเปิดใช้งาน Email/Password ใน Firebase Authentication
2. ตรวจสอบ `databaseURL` และ `apiKey` ใน `firebase.js` ให้ตรงกับ Web App ของ Firebase project
3. Deploy `firebase.rules.json` ไปยัง Realtime Database; ไฟล์ `database.rules.json` เป็นสำเนาเท่ากันสำหรับ workflows ที่ใช้ชื่อเดิม
4. ให้ Firebase Hosting เสิร์ฟโฟลเดอร์ repository root ตาม `firebase.json`
5. เข้า `index.html`; ระบบจะส่งผู้ใช้ที่ยังไม่เข้าสู่ระบบไป `auth.html`

## ตรวจสอบในเครื่อง

```bash
node --test test/accounting-core.test.mjs
node --check accounting-core.js
node --check accounting-store.js
node --check accounting.js
node --check auth-page.js
python3 -m json.tool firebase.rules.json >/dev/null
python3 -m json.tool database.rules.json >/dev/null
python3 -m json.tool firebase.json >/dev/null
```

การทดสอบข้างต้นไม่ใช่การตรวจ hardware, Firebase production หรือการรับรองงบตามมาตรฐานบัญชี/ภาษี รายงานปัจจุบันเป็นเครื่องมือบริหารภายใน ไม่ใช่เอกสารยื่นภาษีหรือใบกำกับภาษี
