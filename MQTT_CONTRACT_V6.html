สวนลุงนะ Smart Farm V7.1 MQTT Contract

This is the active MQTT contract for Firmware V7.1.0-FIELD-STABILITY and the V7.1 web app. The MQTT broker/WSS endpoint, credential flow and existing relay/schedule topics remain unchanged.

Relay

  • Command: smartfarm/relay/{relay}/set
  • Payload: ON or OFF
  • Status: smartfarm/relay/{relay}/status
  • Status payload: ON or OFF

Relay IDs: pump, zone1, lighthome, lightsala.

Control semantics

  • Firmware has no active smartfarm/mode/set or smartfarm/mode/status topic. Do not publish mode commands.
  • Schedules run locally on the ESP8266 from the four-slot schedule topics. Direct relay commands and timers use the existing relay topics.
  • Emergency latch uses the additive command topic smartfarm/emergency/set with EMERGENCY_STOP or EMERGENCY_RESET; status is retained on smartfarm/emergency/status.

Four independent schedules per relay

  • Command: smartfarm/schedule/{relay}/set
  • Payload: { "slots": [ {"enabled":true,"on":"HH:MM","off":"HH:MM"}, ... ] }
  • Maximum: 4 slots per relay.
  • Each relay owns its own four slots; changing one relay never changes another.
  • DELETE clears all four slots for that relay.
  • Status: smartfarm/schedule/{relay}/status
  • Status payload: { "slots": [ ...up to 4 slots... ] }
  • Schedules are stored in ESP8266 LittleFS and continue locally when MQTT is temporarily unavailable.

Relay countdown timer

  • Command: smartfarm/relay/{relay}/timer/set (non-retained).
  • Payload: integer seconds from 1 to 4294967 (about 71,582 minutes), UNLIMITED, 0 or CANCEL.
  • Finite timers turn the selected relay OFF when the explicitly requested countdown expires. Values beyond the technical millis() range are rejected; this is not a 30-minute pump policy.
  • Status: smartfarm/relay/{relay}/timer/status with retained JSON such as { "active": true, "unlimited": false, "remaining": 120 }.

Telegram configuration

  • Configuration command: smartfarm/config/telegram/set
  • Payload JSON: { "botToken": "...", "chatId": "..." }
  • Status: smartfarm/config/telegram/status with JSON { "configured": true|false }
  • Test command: smartfarm/config/telegram/test; any payload requests a test notification.
  • The ESP8266 persists these values in LittleFS; the dashboard does not place them in config.js.

Crop Telegram reminder

  • Command topic: smartfarm/reminder/set; status topic: smartfarm/reminder/status.
  • Commands are settings, upsert, done, snooze, delete, sync and test.
  • Optional task fields include plotId and repeatEveryDays; settings include quiet-hour fields quietStartHour, quietStartMinute, quietEndHour and quietEndMinute.
  • The ESP8266 stores up to eight active reminder jobs in LittleFS and sends Telegram without the Dashboard being open.
  • A successful recurring delivery reports sent_recurring and advances the due date. During quiet hours the device defers delivery and checks again later.

ESP status

  • Online/LWT: smartfarm/status/online
  • Payload: retained true while connected; broker LWT publishes retained false after an unexpected disconnect.
  • Runtime heartbeat: smartfarm/device/status every 10 seconds while MQTT is connected.
  • Heartbeat includes firmware version, free heap, heap fragmentation/max block, RSSI, uptime, reset reason, pump safety lock/runtime, emergency lock/source, RTC validity, DHT11 age/fault counters and Wi-Fi/MQTT reconnect counters.
  • Dashboard considers the device offline after 25 seconds without a heartbeat/presence event.
  • Browser MQTT disconnect does not by itself declare the ESP offline; ESP presence is determined from device messages.
  • Before HTTP or ArduinoOTA firmware writing starts, all relays are forced OFF and schedule application pauses. A failed or aborted update does not reboot the device.
  • The pump has no forced 30-minute runtime cutoff and no automatic MQTT-loss cutoff; a physical E-stop or protective switching hardware is still required for a real pump circuit.

Sensor

Current active sensor is DHT11.

  • Topic: smartfarm/sensor/dht11
  • Payload JSON: { "temperature": number, "humidity": number }
  • No Soil Sensor topic exists; A0 is reserved.

Time

  • DS3231 is supported and used as the preferred local schedule clock when present and valid.
  • I2C: SDA D3/GPIO0, SCL D4/GPIO2.
  • If DS3231 is unavailable or invalid, the firmware falls back to NTP.
  • NTP is used to synchronize DS3231 when Wi-Fi is available; periodic sync interval is 6 hours.

Pump and emergency safety

  • There is no forced 30-minute pump runtime cutoff and no automatic MQTT-loss cutoff.
  • The pump follows the locally stored schedule or the explicit relay/timer command selected by the operator.
  • EMERGENCY_STOP turns all relays OFF, cancels timers and blocks schedule/manual/timer ON until EMERGENCY_RESET.
  • HTTP/ArduinoOTA forces all relays OFF only during the firmware update. ESP8266 boots with all four relays OFF.
  • The software emergency latch is not a physical E-stop; a real pump circuit requires independent protective hardware.

Browser MQTT credentials

  • Username/password are not committed to source control.
  • V7.1 remembers credentials in the browser’s local storage when the user selects the remember option; otherwise they remain session-only.
  • Invalid broker credentials clear the saved browser credentials and reopen the setup dialog.
  • Commands issued during a short MQTT reconnect window are queued for up to 30 seconds and then discarded.
  • A static GitHub Pages client cannot keep a shared MQTT credential secret from the browser; HiveMQ ACLs should be configured for broker-level authorization.

Security

  • Firebase Authentication provides user/admin roles for the web UI and Firebase rules protect role data.
  • User: Dashboard, Relay and schedules. Admin: all user capabilities plus MQTT settings, role management and OTA page.
  • Firmware uses HiveMQ Cloud MQTT over TLS on port 8883. Certificate verification is currently disabled with setInsecure(); transport is encrypted, but server identity is not verified.
  • When PubSubClient reports MQTT_CONNECT_FAILED (state=-2), the firmware reports DNS resolution and a separate TLS/TCP probe on Serial Monitor.
